# 용어 선택 가이드

기술 용어를 한글로 쓸지, 영어 원문으로 쓸지, 음역할지 판단하는 기준이다. 아래 표는 고정된 전체 목록이 아니라 패턴을 보여주는 예시다. 표에 없는 용어는 아래 일반 패턴을 그때그때 적용해서 판단해라. 사용자가 특정 용어를 "이건 이렇게 써줘"라고 명시적으로 지시하면 그 지시가 항상 패턴보다 우선한다.

## 일반 패턴

1. **고유명사와 브랜드명은 영어 원문으로 유지한다.** 제품명, 서비스명, 회사명은 억지로 음역하지 않는다. (Supabase, Redis, GitHub는 "수파베이스", "레디스"로 쓰지 않는다.)
2. **통용되는 한글 표현이 있는 일반 개념어는 한글화한다.** 영어를 그대로 쓰거나 어색한 음역을 쓰지 않는다. (Database → 데이터베이스, User → 사용자, Client → 클라이언트, Server → 서버)
3. **긴 기술 용어와 약자는 최초 1회 괄호로 풀어쓰고, 이후엔 약자만 쓴다.** 형식: `약자 (풀어쓴 표현)`. (VPC (Virtual Private Cloud) → 이후부터는 VPC) 이 규칙을 얼마나 엄격히 적용할지는 독자 유형에 달려 있다. 개발자 대상 문서라면 업계에서 통용되는 약자(API, VPC, RLS 등)는 굳이 풀어쓰지 않아도 된다. 비개발자나 평가자처럼 기술 배경을 가정할 수 없는 독자라면 항상 풀어쓴다.
4. **약자가 문맥상 여러 뜻으로 읽힐 수 있으면 괄호로 의미를 명시한다.** (PC(Program Counter) vs PC(Personal Computer))
5. **한글 개념어 뒤에 대응하는 영어 기술 용어와 제품명을 괄호로 병기할 수 있다.** 패턴 3(약자 풀어쓰기)과 반대 방향이다. 한글이 본문이고 영어가 보충 정보로 괄호에 들어간다. 개발 문서에서 개념을 한글로 설명하면서 정확한 기술 용어를 놓치지 않으려 할 때 쓴다. 추상적인 기능명(Auth, Storage)뿐 아니라 구체적인 제품명(Postgres)에도 적용된다. 특정 제품명만 단독으로 던지면 그게 무슨 역할인지 문맥이 부족할 수 있으므로, 그 제품이 하는 일을 가리키는 한글 개념어를 앞에 붙인다. (로그인(Auth), 파일 저장소(Storage), 데이터베이스(Postgres))
   - 이때 한글 개념어는 영어 단어의 품사와 의미를 정확히 맞춘다. Storage는 "저장하다"라는 동작이 아니라 "저장소"라는 대상을 가리키므로 "파일 저장"이 아니라 "파일 저장소"가 맞다.
6. **약자가 아니어도, 압축된 전문 표현은 독자 눈높이로 풀어쓴다.** "특수 규정(네트워크 격리 요구) 대응"처럼 약자는 아니지만 개념을 압축해서 표현한 문구도 비개발자 독자에게는 벽처럼 느껴진다. 가능하면 문서 안의 구체적인 사례로 바꿔 쓴다 (예: "네트워크 격리 요구" → 이 문서에 이미 나온 "의료정보 보호 규정(HIPAA) 같은 법적 요건이 있을 때"). 표 행 라벨, 다이어그램 노드 이름처럼 짧은 자리라고 예외를 두지 않는다. 오히려 짧은 자리일수록 압축된 전문 표현이 그대로 노출되기 쉽다.

## 예시

| 원어 | 선택 표기 | 근거 |
|---|---|---|
| Database | 데이터베이스 | 패턴 2: 통용되는 한글 표현 |
| Supabase | Supabase | 패턴 1: 고유명사, 음역하지 않음 |
| VPC | VPC (Virtual Private Cloud) | 패턴 3: 최초 1회 괄호 병기 후 약자만 |
| User | 사용자 | 패턴 2: "유저"(어색한 음역), "User"(영문)보다 우선 |
| Client | 클라이언트 | 패턴 2: 음역이 이미 표준적으로 통용됨 |
| Server | 서버 | 패턴 2: 음역이 이미 표준적으로 통용됨 |
| Redis | Redis | 패턴 1: 고유명사, 음역하지 않음 |
| PC | PC(Program Counter) / PC(Personal Computer) | 패턴 4: 문맥상 모호한 약자 |
| Postgres | 데이터베이스(Postgres) | 패턴 5: 구체적 제품명 앞에 역할을 가리키는 한글 개념어 |
| Storage(기능명) | 파일 저장소(Storage) | 패턴 5: "저장"이 아니라 "저장소"로 품사와 의미를 맞춤 |

## 표에 없는 용어를 만났을 때

1. 고유명사인가? → 영어 원문 유지
2. 한글 표현이 이미 널리 쓰이는 개념어인가? → 한글화
3. 길고 처음 등장하는 기술 용어/약자인가? → 최초 1회만 괄호로 풀어쓰기
4. 약자의 의미가 문맥상 하나로 좁혀지지 않는가? → 괄호로 의미 명시

새로 판단한 용어가 반복적으로 쓰일 것 같으면, 이 표에 행을 추가할지 사용자에게 제안해도 좋다. 단, 실제로 추가할지는 사용자 확인을 거친다.
