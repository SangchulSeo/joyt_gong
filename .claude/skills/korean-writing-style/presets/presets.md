# 개인 프리셋 저장소

각 프리셋은 문서 종류(기술문서/자기소개서/보고서)가 아니라 **문체를 구성하는 파라미터 조합**으로 정의한다. 처음엔 비어있는 게 정상이다. 실제로 반복해서 쓰는 조합만 사용자의 명시적 요청으로 쌓아간다.

이 파일을 다루는 규칙은 `SKILL.md`의 3, 4, 5, 6번 흐름과 같다.
- 저장: 사용자가 "저장해줘"라고 명시적으로 말했을 때만 추가한다. 이름은 Claude가 제안하고 사용자가 확정한다.
- 불러오기: 사용자가 프리셋 이름을 직접 말했을 때만 적용한다. 자동 추천이나 자동 적용은 하지 않는다.
- 수정 및 삭제: 명시적 커맨드가 있을 때만 진행한다.
- 기존 프리셋과 겹치지만 다른 요청: 덮어쓰지 않고 일시 적용한다. 저장 여부는 별도로 확인한다.

## 항목 형식

```
### {프리셋 이름}
- 어미:
- 구두점:
- 부분별 혼용:
- 문장 밀도:
- 어휘:
- 비고:
```

## 저장된 프리셋

### 압축 노트체
- 어미: 명사형 종결(개조식)
  - 동사 어미(~함, ~됨, ~ㅁ/음)보다 순수 명사구를 더 우선한다 (예: "정리함"이 아니라 "정리", "달라짐"이 아니라 "변동"). 어미를 완전히 붙일지 명사만 남길지는 그 사실이 문장인지 라벨인지로 판단한다. 존댓말 아님
- 구두점: 온점 항상 생략
  - 어미가 명사형 종결(개조식)이라 공통 규칙상 당연한 결과이지, 이 프리셋만의 선택이 아니다(`common-rules.md`의 "온점" 규칙 참고). **주의**: 온점이 없다고 "여러 사실을 한 줄에 이어붙여도 된다"는 뜻은 아니다. 사실 단위(절)가 다르면 반드시 줄바꿈이나 불릿으로 분리한다. 한 줄/한 문단에 서로 다른 사실 두세 개를 공백만으로 이어붙이면 뭘 말하는지 안 읽힌다. 이건 이 프리셋의 이전 버전에서 실제로 발생한 실패였다.
- 부분별 혼용: 없음
  - 본문 문단과 불릿 모두 동일한 압축 문체를 적용한다.
- 문장 밀도: 개조식, 정보 압축 우선
  - 서술어를 최소화하되, 명사만 나열하지 않는다. 무엇에 대한 나열인지 최소한의 프레임(동사나 조사)은 남긴다. 예: "상시 워커, 장시간 배치, 사설망 접근"처럼 던지지 않고 "~ 기능 필요 시 도입 검토"처럼 목적을 붙인다. 부수적인 세부사항은 다 담으려 하지 말고 핵심 한두 개로 추린다.
- 어휘: 용어집 패턴(`term-glossary.md`) 그대로 따름
  - 고유명사는 영어를 유지하고, 일반명사는 한글화한다.
- 비고: 인프라 비용 정리 문서에서 파생
  - 빠르게 훑어보는 내부 문서나 메모에 적합하다. 압축한다고 정보를 잘라내는 것과 뭉개서 안 읽히게 만드는 것은 다르다. 전자를 하고 후자를 하지 않는다.
